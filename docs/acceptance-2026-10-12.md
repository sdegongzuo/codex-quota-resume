# 0.2.0 开发验收记录

日期：2026-10-12。GPT-6 Luna 子代理负责开发，主代理独立审查和验收。本文评价本工作区 0.2.0 源码，不代表安装版或 GitHub 已更新。当前本机 Codex 桌面包版本为 `26.1007.2314.0`。

## 验收结论

队列、控制、恢复调度和防重链路已完成源码及隔离模拟验收。完整产品验收尚未通过：当前桌面工具没有提供活动上下文用量及真实压缩入口，60% 提前压缩只能交付协调逻辑、配置和明确的能力不足状态。

不能将“可设置 60%”解释成当前桌面已经能压缩，也不能用聊天总结代替真实压缩。后续需接入经过验证的桌面接口，再验证原会话的压缩前后用量、信息保留和真实续跑。

## 已执行的独立验证

- 从当前真实桌面读取工具目录、当前会话返回字段形状及额度字段，确认额度许可和 300 分钟窗口可读；会话快照没有活动 token/窗口字段。检查输出不包含账号值、管道值或聊天正文。
- 独立编写状态机和压缩用例，验证中断排序、单个运行槽位、手动续跑、目录消失保留、120 秒缓冲、60 秒重查、压缩结果不确定的防重、额度许可和新压缩周期标识。
- 启动真实本机 HTTP 面板模块，用隔离模拟数据检查 HTML 和客户端脚本、访问令牌、Origin、配置脱敏、总开关、单项开关和阈值校验。此项属于真实 HTTP 验收，不属于实际点击 GUI 验收。
- 启动真实 `control.mjs watch` 子进程，通过隔离模拟命名管道驱动桌面协议：先发送最早项，原失败未改变时不放行下一项，运行期间保持槽位，新轮次结束后再发送下一项；检查发送前的持久占位、历史保留和 hook 不覆盖手动关闭。
- 检查真实 worker 的互斥、`status` 活性判断及 `stop` 安全退出。仅操作本次隔离验收的进程和 D 盘数据。
- 用独立数据目录运行 CLI，确认无配置时默认开启、60% 默认阈值、120/60 秒默认时间、阈值修改持久保存，以及关闭后下一进程仍读取关闭状态。

## 修复的验收问题

开发初版在独立用例中出现过同时发送多个候选、发送接受后过早释放槽位、忽略最早中断顺序、候选绕过账号级重查间隔、丢弃目录外记录及压缩结果不明仍自动重试。已反馈开发并通过相应独立回归。

最终版本已核对保留发送历史、总开关重新开启恢复后台、手动续跑持续阻挡下一项、停止与本轮完成状态区分、同一会话列表合并、关闭期间刷新连接，以及面板明确显示连接状态。人工核对入口仅登记解除请求，后台确认原会话不是运行态后才释放槽位，原事件不会自动重发。
