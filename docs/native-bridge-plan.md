# Windows 原会话原生控制接入方案

日期：2026-10-13。状态：设计待实现，未修改桌面启动方式，未接通真实压缩或停止。

## 要补齐的行为

1. 已监测原会话达到可调整阈值时，在额度仍可用且工具操作已结束的边界调用真实压缩。
2. 用户从列表停止正在运行的任务时，先持久关闭该项自动续跑，再中断该原会话当前轮次。
3. 读取原后端的用量与轮次事件，确认压缩和停止效果；请求被接受不等于动作完成。

## 当前证据

当前安装的 Windows 桌面通过 stdio 启动自己的 app-server。桌面 bundle 的 CLI resolver 读取 `process.env.CODEX_CLI_PATH`；解析后还会把得到的 executablePath 写入子进程环境。前者是候选路径入口，后者是桌面内部赋值。Windows 需要能直接 spawn 的 exe，不能把 cmd 脚本当作该入口。

当前 bundled CLI 的生成 schema 包含 `thread/compact/start`、`turn/interrupt` 和 `thread/tokenUsage/updated`。插件现有工具管道没有暴露前两项。此证据说明可研究替换启动入口，尚不能证明包装器兼容桌面或拥有目标线程的操作权限。

## 接入结构

桌面 → 原生 exe 包装器 → 原 bundled codex.exe。

包装器只启动桌面本来要启动的一个后端，保持原参数、工作目录和环境。原聊天的 threadId 不变。非 app-server 调用（例如版本探测）原样转发并返回退出码。原后端绝对路径由安装配置指定，必须与包装器不同，防止递归启动。

默认不启用 override。先在隔离环境验证协议，再通过明确的安装步骤启用；切换运行中的桌面需要协调重启，不自动杀进程。

## 协议与权限

- renderer 的 JSONL 流量由单一写队列转发，包装器不写诊断文本到 stdout。
- 所有请求 ID 映射到包装器分配的独立后端 ID，按调用方恢复响应 ID，避免 renderer 与桥接请求碰撞。
- 后端向 renderer 发起的审批请求保留原路由；桥接客户端没有审批代理权。
- 桥接只允许用量订阅、目标状态复核、`thread/compact/start`、`turn/interrupt`。禁止任意 RPC 透传。
- 目标必须在用户持久授权的列表中；中断必须同时匹配 threadId 和最新 turnId。窗口关闭、目标切换或归档不能改发其他线程。
- IPC 仅当前 Windows 用户可访问，另外使用安装时生成的随机令牌。不能只依赖“本地端口”或管道名难猜。
- 仅向已授权目标的订阅者提供事件，去除对话正文、审批内容、凭据和其他线程信息；日志只记动作类型、时间、结果与脱敏关联号。
- renderer 原来的通知保持交付；桥接事件只作为旁路副本，不能消费掉桌面需要的事件。

## 压缩与停止确认

压缩请求前持久记录占位及目标身份。只有原后端报告 contextCompaction 完成且取得之后的用量，才标记完成。超时、断连或重启后的未知结果进入待核对状态，不重试同一次请求。

停止动作先保存用户关闭自动续跑的选择。若目标已结束，显示已结束；若已换轮次，重新取得状态并由本次用户动作明确绑定，不能用旧 turnId 中断新任务。请求接受之后等待该轮次 interrupted/终止事件或状态复核，不以响应成功冒充已停止。

工具执行中不会强制压缩。额度不可用时不启动压缩。用量样本失配、过期或新轮次尚无样本时，不沿用旧样本触发。

## 开发与验收顺序

1. 修复只读 observer 的属性顺序、换轮次、缓存状态和多文件选择问题。
2. 实现独立协议路由器，以对撞 ID、审批反向请求、分片、多通知和断连场景验证。
3. 实现 Windows 原生启动器，使用 D 盘隔离后端验证一个子进程、参数透明和退出语义。
4. 实现有用户 ACL 的 IPC 与白名单。验收未授权用户、错误令牌、未授权线程、过期 turnId 均不能操作。
5. 接入 worker 与任务列表，保留旧工具管道用于已有续跑功能，按能力回执显示按钮。
6. 验证当前 bundled CLI 的真实协议，再协调桌面正常重启接入。完成真实原会话压缩与列表停止验收。
7. 验证自动登记 hook 的信任与加载，进行自然额度耗尽和恢复观察 3～5 次，确认完整需求。

协议模拟通过、exe 构建成功、安装文件存在和桌面实际加载分别记录。任何一个阶段都不能替代后续原会话效果和自然额度恢复验收。
