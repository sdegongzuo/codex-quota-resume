# 状态日志存储

后台状态采用分段差量日志，目录为数据目录下的 `state.jsonl.journal`。

- 首次运行从旧 `state.jsonl` 尾部读取最新有效状态，旧文件原样保留，之后不再向旧文件追加。
- 每个分段以完整检查点开头，后续只记录发生变化的字段；内容相同的保存请求不写入。
- 大于等于 512 字节的记录会尝试无损压缩，仅当压缩后更小时采用；小记录保留明文。重复的会话标识、字段名和观测时间不再大量占用磁盘，恢复后的状态完全相同。兼容已有的明文分段。
- 分段达到 4 MiB 阈值前切换到新分段。单条完整检查点如果超过此阈值，允许独占更大的分段；这是切段阈值，不是当前状态大小上限。
- 程序重启时从最新可恢复分段恢复，随后另起一个分段写入。最新分段只有未写完的检查点时，回退到前一分段。
- 所有原有安全保存时机保留，写入完成后执行 fsync，再允许后续动作。发送占位、结果不确定标记和已处理记录随状态恢复。
- 面板、状态查询和人工核对请求都通过同一个读取入口获取当前状态。
- 上下文观测不保存可由样本时间计算的 `completionDelaySeconds`，也不保存仅用于 rollout 解析的重复 token 总数、输出 token、行号、窗口时间和来源标签。运行时原始观测不受影响。

## 自动清理

持有数据目录互斥锁的后台在切段及每小时检查保留规则，自动清理仅限插件数据目录中的 `state.jsonl.journal` 和 `event-logs`。登记、启停等短命令只写事件，不运行清理，避免清理其他进程正在使用的日志。事件维护由轮询循环驱动，健康期间没有新事件也会检查。

- 状态分段保留 7 天，总量阈值为 32 MiB，超限时从最旧的非保护分段开始清理。至少保留最新两个通过重放验证的可恢复分段，以及它们之后的分段。保护分段优先于天数和大小限制；单个检查点很大时不能承诺严格总量上限。
- 事件日志单段阈值为 1 MiB，保留 7 天，总量阈值为 8 MiB；最新两个分段及当前进程使用的分段受保护。日志写入时触发检查，不另起定时进程。
- 同一进程中相同的后台读取、持久化或启动错误，5 分钟内只记录首次；下一次记录时附上被抑制的重复次数。发送、发送结果不确定等业务事件不作此合并。
- 清理只针对符合固定文件名格式的普通文件，不递归、不跟随符号链接或目录联接。配置、原生操作凭据和其他目录不在清理范围内。
- 最新检查点包含完整队列、发送槽位和已处理记录，清理旧分段不会清除这些防重状态。

旧的 `state.jsonl` 和 `events.jsonl` 原样保留，不纳入自动清理。用户可以在确认新分段可恢复后，按精确路径手动清理旧文件。

降级到只认识旧 `state.jsonl` 的版本会读取过时状态，必须停止后台并完成兼容迁移后才能降级，不能直接启动旧版本。
