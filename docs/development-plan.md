# 自动续跑重新设计开发方案

日期：2026-10-12。需求依据：[已确认需求](requirements.md)。本文是开发计划；本轮仅编写文档。

## 当前实现与差距

以下来自本轮源码阅读，不代表已安装版本的运行验收。

| 当前文件 | 已有行为 | 需要变化 |
| --- | --- | --- |
| `scripts/desktop.mjs` | 桌面命名管道、工具发现、额度读取、轮次读取、消息发送 | 增加能力探测、上下文观测、实际压缩及执行状态适配；接口需验证 |
| `scripts/engine.mjs` | 五小时额度错误识别、恢复许可检查、原失败复查、发送占位 | 5 秒缓冲改为可配置 120 秒；增加列表生命周期、压缩协调和严格串行调度 |
| `scripts/control.mjs` | 显式 enable、全局 disable、status、后台端口互斥、hooks 注册 | 默认开启、持久开关、单项控制、配置命令、列表展示与恢复连接 |
| `scripts/store.mjs` | 追加 JSONL 配置和状态，默认关闭 | 带版本的数据投影、持久历史、跨写入者控制、显式关闭优先 |
| `hooks/hooks.json` | SessionStart 和 UserPromptSubmit | 用于注册和连接刷新；不能依赖用户下一次发消息才发现运行中的 60% 阈值 |

现有后台循环从活动状态移除 sent/cancelled 项，新列表需要保留这些历史；现有 pending 每会话只存一项，不能阻挡同一会话将来的新额度失败。现有目录只覆盖置顶及最近 50 个会话，也不能保证长期等待对象可被再次找到。

## 第一步：验证桌面能力

优先通过当前桌面环境的能力发现及只读调用，验证下表；只有会改变会话的压缩验证才使用专用验收会话。独立 CLI 执行器不作为原桌面会话控制的替代。

| 能力 | 必须确认的证据 | 缺失时行为 |
| --- | --- | --- |
| 上下文占用 | 目标会话当前活动 token、实际窗口、更新时间及计量范围 | 显示无法计算阈值，不用累计会话 token 或文本字符数猜测 |
| 实际压缩 | 原会话压缩入口、允许执行的状态、完成事件或结果、压缩后用量 | 显示不支持自动压缩；阻止发布“60% 压缩已实现”的声明 |
| 额度恢复 | 五小时窗口、重置时间、账号及明确许可 | 未知时保留等待 |
| 会话状态 | 最新轮次、运行/停止/完成/需要输入、归档状态及定向查询 | 无法确认时暂停发送，列表保留 |
| 连续观测 | 运行中 token 更新事件或可用的低成本查询 | 若只能在轮次结束读取，说明阈值有滞后，评估是否满足提前压缩要求 |

先调查当前桌面工具；如其缺少必要接口，再验证桌面实际使用的 app-server 控制能力、连接和授权边界。不能根据上游接口名称推定当前桌面能调用，也不能通过人工修改 token 用量配置假装扩大实际窗口。

产出能力表及脱敏原始回执，存入 D 盘项目证据目录。未验证能力作为明确的开发阻塞项记录，不要求用户凭空选择技术实现。

## 模块与数据设计

保留 `control.mjs` 作为入口，`desktop.mjs` 隐藏桌面协议细节。新增职责模块：

- `queue.mjs`：列表状态转换、候选校验、顺序与单个运行槽位。
- `compaction.mjs`：60% 触发、边界等待、单次请求、结果核对与重新布防。
- `scheduler.mjs`：恢复时间、两分钟缓冲、60 秒重查及重启后到期补查。
- `settings.mjs`：默认值、范围校验及全局/单项持久开关。

这是一版职责划分，避免为每个状态单独建文件。`engine.mjs` 协调这些模块，协议和列表状态不能散布到 UI。

建议配置：

```json
{
  "schemaVersion": 2,
  "enabled": true,
  "compactionThresholdRatio": 0.6,
  "resumeBufferSeconds": 120,
  "recoveryRetrySeconds": 60,
  "discoveryIntervalSeconds": 30,
  "maxActiveAutoResumes": 1
}
```

30 秒是候选发现轮询的建议初值，区别于恢复失败后的 60 秒重查；运行中上下文优先事件观测。比例验证为 0～1 之间的有效值，并根据已验证的实际压缩限制约束可接受范围；每项配置显示单位。

队列记录至少含 accountId、hostId、threadId、会话名称、失败 turnId、中断时间、resetAt、eligibleAt、autoResumeEnabled、状态及原因、发送标识、时间戳。使用账号/宿主/会话/失败轮次组合识别同一次中断，按中断时间排序，以稳定标识打破同时间并列。

上下文状态独立记录当前窗口、活动 token、观测时刻、阈值配置版本、压缩周期、请求标识和压缩前后用量。不持久保存无关聊天全文或凭据。

继续采用追加记录及投影恢复，不删除历史。控制命令和后台共用单一写入协调，防止全局/单项关闭被旧状态覆盖。旧配置迁移时保留显式 disable、目标记录和 sending/uncertain 状态；缺省新配置才默认开启，不能把旧手动关闭解释成未配置。

## 执行流程

1. 插件正常加载后建立连接、加载配置；hooks 注册主会话并刷新连接，排除子代理。默认开启只用于无持久设置的首次初始化。
2. 运行中观测活动上下文，达到 60% 且仍有明确额度许可时，登记待压缩请求。
3. 在验证过的安全边界执行一次实际压缩，确认完成与前后用量。压缩后低于阈值才重新布防；仍高于阈值显示原因，不循环请求。切换模型或调阈值时重新评估窗口和布防状态。
4. 结构化额度失败与五小时耗尽同时出现时建立候选，记录压缩状态及 `eligibleAt = resetAt + 120`，加入列表。
5. 到期后检查实际额度；未恢复则更新下一次检查到 60 秒后。应用不可用时保留记录，重连或唤醒后按当前时间补查，不补发积压动作。
6. 取得全局运行槽位，选择最早的可执行候选。复查账号、原会话、最新轮次、所有开关及用户操作。新指令淘汰旧失败，明确停止关闭该项；需要输入的任务不自动继续。
7. 如确有待补压缩且接口允许，恢复额度后先完成压缩，再重新核对发送条件；不支持压缩时显示原因并继续评估正常续跑。
8. 持久化发送占位后发送原会话继续指令。成功仅表示消息接受，随后观测实际开始运行；超时、崩溃或回执不明标记结果待核对，禁止自动重发。
9. 槽位保持到该会话本轮结束、失败、停止或需要用户输入。不要仅在消息接受后释放。用户手动启动其他列表会话时也需更新槽位判断，避免自动再启动一个会话。
10. 再次额度耗尽可创建新中断事件；旧发送结果及手动关闭历史保留。全局关闭停止未来自动动作；停止正在运行的任务需要单独明确操作，不能把总开关等同于强行中断。

仍须披露：若桌面没有原子“核对失败轮次并发送”接口，最终复查与发送之间有竞争窗口。实现降低窗口并记录回执，不承诺绝对一次投递。压缩请求也采用持久请求状态，结果不确定时先核对而非直接重试。

## 列表与控制入口

第一版提供列表查询和控制命令作为所有界面的共同入口，支持 list/status、全局开启关闭、单项开启关闭、配置读取修改。用户可从控制会话操作指定目标，无需让正在执行的目标会话自行配置插件。

同时交付可手动操作的本地列表面板，展示状态、原因、原会话入口、预计续跑时间、总开关、单项开关和 60% 阈值设置。具体承载优先验证插件可用 UI 能力；若不能嵌入 Codex，采用本机回环网页并在 Codex 面板打开。此承载选择由能力验证决定，不能假定插件可以直接增加桌面侧栏。

本地面板状态变化走同一控制入口并立即生效；写操作需限于本机且校验来源与会话凭证，不能开放无校验的网络控制端口。关闭项目保持可见；待核对发送项目可查看原会话后人工解除，不能提供含糊的自动重试按钮。

## 开发顺序与验收

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| 1. 能力验证 | 上下文/压缩/状态接口证据与限制 | 确认当前桌面能观测和实际压缩原会话，或明确阻塞原因 |
| 2. 状态与控制 | 配置迁移、持久列表、默认开启、单项及总开关 | 关闭不被 hook 覆盖，历史保留，多写入和重启正确 |
| 3. 恢复调度 | 120 秒缓冲、60 秒重查、串行槽位、失败事件防重 | 只向正确原会话发送，实际运行串行，结果不明不重发 |
| 4. 提前压缩 | 60% 可调阈值、边界处理、完成核对、观测记录 | 仍有额度时真实压缩成功，重复事件/重启不重复执行 |
| 5. 用户界面 | 可操作列表面板、配置与状态说明 | 用户能关闭单项和全部，状态与后台一致，重开持久生效 |
| 6. 实机观察 | 安装身份、hooks、真实压缩及额度恢复回执 | 完成真实链路并观察 3～5 个完整周期，给出阈值调整建议 |

后续实现时做有意义的状态机和模拟链路验证：阈值边界、压缩中额度耗尽、配置改动、两分钟边界、60 秒重查、串行运行、手动停止/继续、新轮次、账号切换、断连重连、休眠、重启、发送结果不确定及旧配置迁移。

模拟验证之后检查打包/安装/运行身份、hooks 是否真实生效、面板操作和原会话压缩效果。自然额度耗尽后的恢复验收单独记录；没有发生真实耗尽与恢复时，交付报告必须保留这一未验证边界。

所有新数据、证据和临时产物使用明确 D 盘路径。沿用禁止删除文件规则；迁移采用追加事件，不清空、覆盖或移动旧记录。
