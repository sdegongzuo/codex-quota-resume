# 自然额度耗尽漏采修复

## 实际失败

本次自然额度耗尽后，真实主聊天保留了明确额度失败，但插件没有中断记录和待续跑任务。这次完整流程验收失败；此前安装、信任配置、进程在线及单元测试通过，不能代替真实自动登记和恢复续跑通过。

只读核对发现该聊天未登记进监控。两个 hooks 已信任，但没有真实自动登记回执。后台进程仍在线，日志有多次桌面读取失败，旧诊断只保存笼统错误，无法事后确定具体方法或错误类别。读取时官方额度已经恢复，旧逻辑也会因没有同时观察到耗尽而丢弃候选。这些证据不足以认定历史连接故障的准确底层原因。

## 修复行为

- 后台从同一 host 的主 Codex 聊天目录发现目标，不以 hooks 执行成功作为唯一登记方式；排除其他 host、ChatGPT 聊天及显式子代理信息。发现事件不修改控制聊天的管道身份，也不覆盖已有关闭选择。
- 以原监测起点限定失败轮次，登记后持久保存目标。检查中的并发关闭会阻止登记及发送。目录接口仍有范围限制：全部置顶聊天及最近 50 个非置顶聊天；未在目录中的任务不能发送。
- 读取目标前保存官方额度观测，按账号保留近期两组耗尽窗口的首末观测及近期许可观测，防止普通轮询挤掉耗尽证据。仅与中断时段相近且账号一致的官方恢复时间可用于续跑。
- 明确额度错误但恢复时间证据缺失时，持久保留 `needs_review` 候选；预计续跑显示“恢复时间待核对”，不伪造倒计时。候选不等于已确认五小时中断，不能从错误文案或新额度周期猜测过去的恢复时间。
- 单个聊天读取失败保留安全方法和错误码，继续读取其他目标。实际发送仍须准确失败轮次、服务恢复时间加 120 秒、账号匹配、当前许可、实时关闭复查及持久发送占位。
- 已有自动续跑仍占据唯一执行槽位，但不会让后台停止收集中断候选。压缩协调失败也不丢弃此前采集的中断记录。
- 连接状态每轮更新成功时间；关键接口失败与部分聊天失败分别显示，超过 90 秒没有新检查时显示过期，不把存活进程等同于正常监测。

## 验证与边界

隔离回归先复现未发现目标、恢复后丢弃记录和目标读取失败阻断其他聊天，再验证修复。主代理另用真实桌面数据执行只读采集：发现漏登记的主聊天，原额度失败进入 `needs_review`，关闭目标保持关闭，聊天写入尝试为零。此回放的配置和状态写在 D 盘隔离证据目录，不修改真实任务数据。

主代理独立重跑全仓测试 92/92 通过。增量安装的 9 个资源与源码哈希一致，后台切换后实际发现 10 个新主聊天，任务配置共 13 项（包括保留关闭的目标）；原额度失败候选已进入真实持久列表，状态为 `needs_review`。后台连接连续更新为 available，列表 `/api/state` 返回 HTTP 200 并包含该候选；更新后没有 sending、sent 或 uncertain 事件。

运行文件更新采用 D 盘备份后的增量同步，不再次执行会清理旧缓存的插件安装命令。hooks 定义不变，无需重新授权信任。后台和列表更新不要求重启 Codex。

这轮只证明采集修复及关闭、防重复边界。真实自动续跑和真实压缩仍须独立验收；继续按用户要求等待自然额度耗尽，不主动耗尽额度或向真实聊天注入测试消息。当前旧原生 host 的压缩通道限制仍保留。
