## Standards 审查

1. 状态日志切段时，打开新文件的操作位于失败恢复范围之外。已有分段切换到新分段时若打开失败，内存中的文件名已前进，后续保存可能持续尝试读取不存在的文件。已将打开操作纳入恢复范围，失败后重新生成完整检查点。回归测试注入真实 Node 文件系统调用层的 `EACCES`，验证重试恢复且不丢发送占位。
2. 多个命令进程都执行事件日志清理，可能清掉长驻后台正在使用但不是最新两个的分段。现仅持有互斥锁的后台执行清理，短命令只写日志；后台轮询主动驱动每小时维护，健康期间没有新事件也会检查。回归测试验证多个短命令和后台维护均保留后台当前分段及已有记录。

## Spec 审查

1. 重复错误的抑制状态先于实际写入更新。首次写入失败后，同一错误的首次成功重试可能被抑制。现仅在写入成功后更新去重缓存和计数。回归测试注入一次追加失败，验证下一次重试确实生成记录。
